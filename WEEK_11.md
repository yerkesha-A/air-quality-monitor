# Неделя 11 — нативные возможности Android

Проверка: 29 октября 2026. **Статус: частично выполнено — физический Android ещё не проверен.**

## Реализация

`AccountScreen` использует настоящий `image_picker`: камера Android и системная галерея. Круглый аватар остаётся прежним по дизайну. `LocalAvatarStore` атомарно сохраняет изображение в приватные документы приложения по Firebase UID; локальное фото имеет приоритет перед сетевым Google-аватаром. Отмена не меняет профиль. Ошибка камеры показывает понятное сообщение с предложением галереи.

Собственный канал `air_quality_monitor/device` связывает Dart `DeviceService` и Kotlin `MainActivity`. Метод `getDeviceInfo` возвращает настоящие `Build.MODEL`, `Build.VERSION.SDK_INT`, BatteryManager и признаки доступности локальной конфигурации. Это собственный канал, а не обёртка только над готовым плагином.

Kotlin возвращает `result.error` при исключении и `notImplemented` для неизвестного метода. Dart обрабатывает `PlatformException`, `MissingPluginException` и null: данные недоступны, а не выдуманная модель/батарея. Экран не показывает фиктивный результат.

## Автоматические проверки

- Unit-тесты MethodChannel: корректный payload, недоступный плагин, PlatformException, null.
- Widget-тесты: camera/gallery передают выбранные байты; отмена и повторное открытие не меняют аватар; ошибка доступа не изменяет фото; круглый размер 88 px и адаптивность.
- LocalAvatarStore: разделение UID, чтение после повторного открытия хранилища и атомарное сохранение.

Native-проверка на отдельном AVD выполняется отдельным opt-in integration-тестом. Он требует compile-time разрешение и локальный marker-файл, чтобы случайно не заменить аккаунт/аватар основного AVD. `--no-uninstall` обязателен. Используются реальные Android camera/picker, без подмены image_picker.

## Фактическая проверка эмулятора

На отдельном AQM_Weeks_09_11 (Android API 37) native integration-тест прошёл 1/1 с `--no-uninstall`:

- настоящий `getDeviceInfo` вернул Android SDK/модель; неизвестный метод вернул MissingPluginException;
- реальная камера открылась, снимок подтверждён, аватар сохранён в приватный файл;
- повторный запуск камеры выполнен при повторном прогоне без падения;
- системный Android Photo Picker выбрал копию фактического снимка из Pictures, аватар обновился;
- новый экземпляр LocalAvatarStore прочитал тот же путь к фото;
- дополнительно прошли серверное чтение Firestore, настоящий foreground FCM push и disk-cache test.

## Приёмка на физическом телефоне

Телефон пока не участвовал в проверке. Для завершения:

1. Android 7.0+ → включить «Для разработчиков» → «Отладка по USB».
2. Подключить USB и подтвердить RSA-диалог. Проверить `flutter devices`.
3. Использовать тестовый аккаунт. Если приложение уже установлено, сначала сверить package/подпись и сохранить данные; не делать uninstall при несовпадении подписей.
4. Открыть аккаунт → Изменить фото → Сделать снимок → подтвердить. Повторить камеру и отменить. Выбрать фото из галереи, затем отменить повторный выбор.
5. Полностью закрыть приложение через Android и снова запустить. Проверить тот же аккаунт и фотографию.
6. Профиль → информация об устройстве: сверить реальную модель, SDK и батарею; при отсутствии батареи допускается отсутствие значения.
7. При доступном разрешении камеры проверить отказ и повторный запуск; GPS и выключенную службу проверить по сценарию недели 9.

Фотография профиля и данные аккаунта не публикуются. Для отчёта достаточно снимка камеры/диалога информации без имени/email и краткого результата приёмки. До физической проверки неделя не объявляется завершённой.
