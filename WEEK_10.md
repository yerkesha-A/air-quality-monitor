# Неделя 10 — производительность

Проверка: 29 октября 2026. **Статус: частично — требуется восстановить подтверждённый снимок Memory до оптимизации.** Измерения и ограничения — ниже; физический телефон не использовался для измерений.

## Что изменилось

- Главная (почасовой прогноз) и поиск города используют существующие `ListView.builder`.
- Заметки и уведомления используют настоящую бесконечную прокрутку. `SliverList.builder` находится в общем `CustomScrollView`, без вложенного `shrinkWrap`-списка. Это sliver-аналог `ListView.builder` с ленивым созданием строк. SQL keyset запрашивает 21 запись, показывает 20, следующая порция загружается у конца viewport. Есть spinner, повтор ошибки, защита от одновременных запросов/дубликатов/зацикливания и конец списка.
- История ограничена выбранным периодом до 31 дня: почасовые точки нужны графику, календарю и статистике. Детальный список остаётся постраничным; он не выдаётся за бесконечный. Избранное — небольшой список, лишняя пагинация не добавлялась.
- Настоящий сетевой Google-аватар использует `cached_network_image`: disk cache, ограничение размера декодирования, placeholder и fallback при ошибке. Если аккаунт не содержит URL фотографии, показываются инициалы. Сохранённая локальная фотография имеет приоритет; искусственные картинки в интерфейс не добавлялись.
- График больше не требует repaint при каждом обновлении родителя: сравниваются точки/выбранная точка/цвета, `RepaintBoundary` отделяет его от окружения. Повторный drag по той же точке не вызывает `setState`. Экран истории подписан на необходимые части состояния и не перезагружает данные на каждый промежуточный state BLoC.
- Новые слушатели прокрутки, контроллеры и lifecycle observer освобождаются в `dispose`; поздние ответы после dispose игнорируются. Применён `const`, где возможно.

## Настоящее сравнение до/после

Flutter 3.47.5, profile mode, Android API 37 ARM64, отдельный AQM_Weeks_09_11, 1080×2400, 4 CPU / 3072 MiB / host GPU. Перед обоими замерами Gradle daemon остановлен. Одинаковый гостевой аккаунт и Алматы, три одинаковых цикла: прокрутка главной → история → карта → профиль → главная. Maps ещё без Cloud-ключа, сетевого аватара в гостевом профиле нет. Их нагрузку эти числа **не измеряют**.

До production-изменений сохранён baseline; после — повторён тот же сценарий длительностью около 37 секунд. FrameTiming получен из движка Flutter, память — через VM Service с интервалом 2 секунды и явным GC до/после. DevTools Performance/Memory подключён к реальному profile-процессу. Дополнительная трассировка widget builds выполняется отдельно от сравнения.

| Показатель | До | После |
| --- | ---: | ---: |
| Реальные кадры | 1119 | 1152 |

| Build p95, мс | 7,850 | 7,110 |

Хвост распределения raster сократился примерно на 17,6%, build p95 — на 9,4%. Медиана build и память выросли; улучшение всех показателей не утверждается. Одно сравнение на эмуляторе не доказывает статистическую значимость, отсутствие утечек или стабильные 60 FPS. Heap — память Dart isolate, а не вся RSS приложения/эмулятора. Остаточный raster jank требует отдельной проверки на телефоне. Переключение раннего пробного запуска SwiftShader на host GPU не включено в сравнение: оба формальных замера выполнены с host GPU.

## Воспроизводимость и тесты

[Profile entrypoint](tools/week10_profile.dart) регистрирует только измерительные расширения; обычное приложение по-прежнему запускает `lib/main.dart`. [Одинаковый сценарий](tools/measure_android.dart) принимает путь к приватному VM URI, выходную папку и ADB serial.

```sh
flutter run --profile -t tools/week10_profile.dart -d <test-device>
dart devtools
# Остановить Gradle daemon, подключить DevTools к VM приложения.
dart tools/measure_android.dart <private-uri-file> <private-output-dir> <test-serial>
```

[Тесты пагинации](test/infinite_records_test.dart) проверяют реальную прокрутку viewport, ленивое построение, ключи, конец, ошибку/retry и dispose. Дисковый кеш отдельно проверяется native integration-тестом: настоящий HTTP-ответ → остановка fixture-сервера → удаление только fixture из memory ImageCache → повторное декодирование из диска. Native-тест этого сценария прошёл на отдельном Android API 37. Fixture используется исключительно тестом, не добавляется в продукт.
