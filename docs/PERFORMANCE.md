# Пагинация, изображения и профилирование

Аудит 16 октября 2026. Этот документ разделяет существующий код оптимизаций, фактические измерения и оставшуюся работу.

## Пагинация

`LocalStore.notesPage`, `alertsPage` и `historyPage` выполняют keyset-запросы в SQLite с `LIMIT 21`: 20 строк для страницы и одна для определения продолжения. Курсор заметок/уведомлений — `(created, id)`, истории — `time`. `PagedRecords` используется на экранах заметок, уведомлений и в списке истории; доступны следующие/предыдущие страницы и повтор после ошибки. Среднее и график истории рассчитываются отдельно по доступному периоду.

Доказательства: [LocalStore](../lib/data/local/local_store.dart), [PagedRecords](../lib/presentation/widgets/paged_records.dart), [widget-тест](../test/pagination_test.dart), [нативная проверка SQLite](../integration_test/support/sqlite_pagination.dart). Тест проверяет 45 записей, границы, окончание списка, возврат и ошибку. Поиск городов ограничен ответом Open-Meteo и не заявляется серверной пагинацией.

## Кеширование изображений

`Image.asset`, `Image.file` и `Image.network` используют стандартный Flutter ImageCache в памяти процесса. Автоматическое кеширование через ImageProvider описано в [официальной документации Flutter](https://api.flutter.dev/flutter/painting/ImageCache-class.html). В `nature_components.dart` декодирование фона ограничено `cacheWidth: 1000`, миниатюры — 160 px. В `AccountAvatar` размер декодирования зависит от размера аватара и pixel ratio. Повторный provider/key переиспользует декодированное изображение, пока оно остаётся в ImageCache. Локальные фото сохраняются по UID в app documents и переживают перезапуск; это хранение файлов, а не дисковый HTTP-кеш.

**Отдельного дискового кеша сетевых аватаров / CachedNetworkImage нет.** При новом процессе без сети для ранее не сохранённого Google-аватара показываются инициалы. Нельзя называть это полноценным offline-кешем сетевых изображений.

Доказательства: [фоны](../lib/presentation/widgets/nature_components.dart), [аватар](../lib/presentation/widgets/account_avatar.dart), [локальные фотографии](../lib/data/local/local_avatar_store.dart), [тесты хранения](../test/local_avatar_test.dart).

## Фактические результаты DevTools

Сохранены реальная запись Android VM timeline (32 566 событий), 20 измерений памяти с шагом 3 секунды и [скриншот Flutter DevTools Performance](screenshots/devtools-android-performance.png). Файлы записи находятся в приватной `.local-backups/android-completion/performance/`; наружу вынесены только [агрегированные результаты](rk1/evidence/performance-summary.json). VM service URI, raw trace и личные сведения не публикуются.

| Метрика сохранённой записи | Значение |
| --- | --- |
| Период измерения памяти | 0–57 с, 20 точек |
| Dart heap, начало / конец | 15,14 / 20,10 MiB |
| Максимальный Dart heap | 31,03 MiB |
| Heap после завершающего GC | 18,13 MiB |
| BUILD events, медиана / p95 | 0,24 / 56,05 мс, 217 пар событий |
| GPURasterizer::Draw, медиана / p95 | 904,46 / 1793,68 мс, 42 полные пары |

Метод: длительности получены из пар `B`/`E` с одинаковыми pid/tid/name; незавершённые пары на границах записи исключены. BUILD и engine raster events — не замена `FrameTiming` и не самостоятельный FPS-тест. Скриншот DevTools показывает slow frames: достижение 60 FPS не подтверждено. Одна короткая запись и снижение heap после GC не доказывают отсутствие утечки памяти. Режим сборки и аппаратные условия исходной записи недостаточно описаны; эти числа нельзя переносить на физический Android или сравнивать с release как бенчмарк.

Таким образом, **результаты профилирования есть, но требование полной оптимизации производительности ещё не закрыто**. Следующая приёмка: profile build на отдельном устройстве, фиксированный сценарий прокрутки/смены вкладок, UI/raster FrameTiming, повторный замер памяти и проверка дорогих raster/blur операций. Дизайн ради отчёта не менялся.
