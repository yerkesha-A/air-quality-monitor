# Вопросы к защите

1. **Почему Flutter и Dart?** Один интерфейс на виджетах, строгие типы и null safety; асинхронные запросы не блокируют UI. В этом проекте проверена Android-версия, работоспособность iOS не заявляется.
2. **Зачем Provider и BLoC вместе?** Provider передаёт зависимости и простые общие настройки. BLoC управляет событиями загрузки воздуха, поиска и истории с явными loading/error/success.
3. **Чем Repository отличается от экрана?** Экран отображает состояние, Repository выбирает API или локальный кэш и преобразует данные в доменные сущности.
4. **Как устроена Dependency Injection?** AppDependencies собирает реализации; конструкторы получают контракты. В тестах вместо сети внедряются mocktail и тестовые хранилища.
5. **Откуда берутся AQI и JSON?** Из настоящего REST API Open-Meteo, модель CAMS. DTO используют json_serializable. Это модельная оценка, а не показание установленного рядом датчика.
6. **Что происходит без интернета?** Repository возвращает сохранённые SQLite-данные с исходным временем. Настройки хранятся в SharedPreferences. Без предыдущего кэша интерфейс показывает ошибку или пустое состояние.
7. **Как защищён Firestore?** Правила ограничивают профиль и вложенные данные UID авторизованного пользователя; тесты проверяют разрешённые операции и отказ чужому UID. Клиентская защита маршрутов не заменяет серверные Rules.
8. **Чем настоящий FCM отличается от локального уведомления?** FCM приходит с сервера через Firebase; локальное создаёт сам Android-клиент. В проекте эти сценарии проверяются отдельно, включая переход по нажатию.
9. **Почему OSM вместо Google Maps?** Чтобы пользоваться картой без Google Cloud billing. Тайлы OSM сопровождаются атрибуцией. Это функциональная замена, дословное требование Google Maps нуждается в согласовании преподавателя.
10. **Что делает MethodChannel?** Dart вызывает собственный Kotlin-обработчик для сведений об Android-устройстве. Неизвестный метод возвращает notImplemented. Виртуальная камера и GPS эмулятора не доказывают работу физических датчиков.
11. **Что означает покрытие?** Доля исполненных строк инструментируемого Dart-кода по LCOV. Порог задания — выше 40%; это не гарантия отсутствия ошибок и не покрытие Kotlin или Firebase Console.
12. **Что проверяет CI?** GitHub Actions устанавливает зависимости, проверяет формат, analyze, тесты и покрытие, собирает APK и сохраняет артефакт; отдельно проверяет Rules. Новый локальный код становится подтверждённым CI только после разрешённого push и зелёного запуска.
13. **Для чего Crashlytics и подпись release?** Crashlytics собирает ошибки; non-fatal проверяется отдельно от настоящего падения. Существующий ключ подписывает APK/AAB; пароли, ключ и символы не публикуются в исходниках. Отправка App Distribution не означает физическую установку APK.
