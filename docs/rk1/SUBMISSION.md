# Что отправить преподавателю

Комплект подготовлен 16.10.2026. GitHub пока ожидает отдельного разрешения на первую публикацию; не отправляйте несуществующую ссылку.

## Минимальная сдача

1. **Ссылка GitHub** после разрешённой публикации и проверки доступа преподавателя. В репозитории: README, RK1_REPORT.md, исходники, Dart-задания, эскизы, скриншоты, тесты и CI workflow.
2. **AirQualityMonitor-release.apk** из локальной папки `submission/RK1_2026-10-16/`. Это подписанный обычный Android release, включает Firebase-конфигурацию и готов к установке на отдельное устройство. Не ставить поверх основного debug-приложения владельца: подписи отличаются.
3. **RK1_REPORT.pdf** — готовый PDF для чтения/печати. Редактируемый **RK1_REPORT.md**, **docs/rk1/VALIDATION.md** и **docs/rk1/SCREENSHOTS.md**. Все входят в source.zip и в подпапку source локального комплекта. При отправке отдельно сохраняйте структуру папок, чтобы ссылки работали.
4. При необходимости файл **source.zip**: чистые исходники и материалы, без keystore, паролей, SQLite, токенов и личных данных. Готовый APK отправляется отдельно, не добавляется в Git.

AAB включён как дополнительный подписанный артефакт; на телефон его напрямую не устанавливают. Для защиты использовать APK. Google Play не требуется.

## Запуск без настройки разработки

- На подготовленном Mac открыть исходный Android Emulator: установленное приложение, прежний аккаунт и локальные данные сохранены. На главной выбран Алматы, есть кеш и история.
- На новом Android 7+ устройстве передать APK и установить обычным Android installer с разрешением установки из выбранного источника. Нужен запас диска и интернет для новых API-данных/Firebase; настройки ключей на телефоне не нужны.
- Нажать «Начать», затем «Продолжить без аккаунта» для мгновенного показа мониторинга или войти в собственный Google/Email-аккаунт для Firebase.
- Выбрать город, дождаться AQI. Проверить историю, темы и уведомления. На новом устройстве локальная история начинается с новых запросов — личная база владельца не переносится.
- Google-вход на отдельном release AVD уже подтверждён владельцем и сохранён после полного перезапуска. Установка на физическом смартфоне преподавателя отдельно не выполнялась.

## Перед защитой

Открыть [сценарий 5 минут](DEFENSE_5_MIN.md). Подготовить README и матрицу недель. Проверить интернет и открытый город. Не запускать integration tests/учебный Flutter target на основном AVD. Не выходить из аккаунта владельца ради показа регистрации. Для демонстрации ошибок достаточно тестов; для реального нового пользователя — отдельное устройство/AVD.

## Что не отправлять

Не отправлять `.local-backups`, app data AVD, пароли тестовых аккаунтов, signing keystore, `android/key.properties`, `android/local.properties`, service account keys или токены. Приватный `google-services.json` не включается в исходники; он уже обработан при сборке APK. Для самостоятельной Firebase-сборки преподавателю потребуется согласованная конфигурация; гостевой исходный код собирается без неё.
