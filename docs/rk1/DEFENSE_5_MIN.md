## Ответы на вероятные вопросы

- **Почему BLoC и Provider вместе?** BLoC описывает события/состояния асинхронного AQI/поиска/истории. Provider передаёт зависимости и небольшие ChangeNotifier-модели. Локальные элементы формы остаются в setState.
- **Зачем Repository?** Экран не зависит от HTTP/SQLite. Контракт можно подменить тестовым объектом; production использует реальный API.
- **Что происходит без сети?** Кеш сохраняет исходное время, UI обозначает его; отсутствие кеша даёт понятное состояние ошибки/пустоты.
- **Где безопасность?** Права Firestore по UID, запрет чужих данных и server-only записей. Секреты, ключ подписи, SQLite и токены исключены из Git.
- **Что сохраняется после перезапуска?** SDK-сессия Auth, preferences, SQLite, локальные фото; сохранность проверялась отдельно от UI-тестов.
- **Можно ли поставить преподавателю?** Да, готовый подписанный APK включает конфигурацию. На новом устройстве аккаунт преподавателя, без доступа к локальным данным владельца; для свежего API/Firebase нужен интернет.
