# Восстановление после перезагрузки Mac — 16 октября 2026

## Причины и исправления

Сбой `impellerc -9` подтверждён системным логом macOS: AppleSystemPolicy
запретил запуск `.../engine/darwin-x64/impellerc` в 21:22:58 и 21:23:01.
У бинарника был `com.apple.quarantine`; `codesign --verify` прошёл.
Атрибут снят только с этого файла. Глобальные настройки защиты не менялись.
После этого debug-сборка успешно завершилась. OOM как причина этого сбоя
не подтверждён. Отчёт о перезагрузке содержит отдельный watchdog timeout
(`no checkins from watchdogd in 93 seconds`), а не доказательство OOM.

На Mac 8 ГБ RAM исходный Gradle допускал heap 8 ГБ и metaspace 4 ГБ.
В `android/gradle.properties` установлены heap 2 ГБ, metaspace 768 МБ,
один worker, без параллельных Gradle-задач, Kotlin compiler in-process.
Исходники приложения и версии зависимостей при восстановлении не менялись.

Первая release-сборка выявила отсутствие зависимости между задачей Crashlytics
`injectCrashlyticsVersionControlInfoRelease` и генератором AGP
`extractReleaseVersionControlInfo`. В `android/app/build.gradle.kts` добавлен
`dependsOn`; порядок проверен через dry-run, служебный файл перенесён в приватную
копию, а следующая сборка успешно создала его заново.

При переключении debug → release флаг `--no-pub` оставил старый
`GeneratedPluginRegistrant.java` с dev-плагином `integration_test`, которого нет
в release classpath. Причина подтверждена исходниками установленного Flutter:
`regeneratePlatformSpecificToolingIfApplicable` пропускает регенерацию при
`shouldRunPub=false`, а `injectPlugins(releaseMode: true)` исключает dev-плагины.
Для release использована штатная `flutter build appbundle --release`, без
`--no-pub`. Lockfile и версии зависимостей остались прежними. При переключении
режимов сборки следует разрешать штатную регенерацию служебных файлов.

## Состояние эмулятора

AVD `Medium_Phone_API_37.0`, Android API 37, загрузился.
Package Manager хранит запись `com.example.air_quality_monitor` с
`installed=true`, appId 10243 и каталогом `/data/user/0/com.example.air_quality_monitor`,
но показывает `pkg=null`. Каталог APK, указанный в `codePath`, отсутствует;
`pm path` не возвращает APK. Поэтому `run-as` сообщает `unknown package`.
Причина исчезновения каталога APK не установлена.

SELinux-лог подтверждает существование каталога app data и его inode.
Содержимое текущей SQLite, preferences, Firebase-сессии и фотографий прочитать
не удалось: AVD не root/debuggable, а пакет не доступен для `run-as`.
Полная сохранность текущих данных поэтому **не подтверждена**.
Архивы `.local-backups/profile-firebase/app-data-before-profile.tar` и
`.local-backups/stage2/android-data-before-real-auth.tar` читаются полностью;
SQLite из последней profile-копии прошла `PRAGMA integrity_check`: `ok`.
Это копии до предыдущих работ, они не гарантируют наличие самых новых данных.

Удаление/переустановка приложения, wipe data, flutter clean, изменение SQLite,
восстановление архивов и сброс эмулятора не выполнялись. Интеграционные тесты,
которые устанавливают приложение или меняют облачные данные, не запускались.
Восстановление пакета требует отдельной оценки и разрешения владельца.

## Проверки

- `flutter doctor -v`: Android toolchain и лицензии в порядке; Flutter 3.47.5,
  Dart 3.13.4, SDK работает через Rosetta. Неполный Xcode относится к отложенному iOS.
- `flutter analyze --no-pub`: без замечаний.
- `flutter test --no-pub --concurrency=1`: 71/71.
- `flutter build apk --debug --no-pub`: успешно; ZIP APK проверен.
- Release AAB: успешно, `build/app/outputs/bundle/release/app-release.aab`,
  62 898 849 байт. `jarsigner -verify` подтвердил подпись; SHA-256 сертификата
  подписанта совпал с сертификатом существующего upload-keystore; ZIP целый.

Штатный online-запуск после R8 ожидал сетевой ответ Google Play SDK Index
в Android Lint (подтверждено thread dump). Остановлен только Gradle-клиент этого
запуска; сборка завершена через Gradle offline, без отключения Lint:

```sh
# После штатной регенерации release tooling через flutter build appbundle --release:
cd android
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:bundleRelease --offline --console=plain
```

`lintVitalRelease` прошёл, итог `BUILD SUCCESSFUL in 3m 16s`.
Offline-режим не обновляет сетевой SDK Index. Он не заменяет проверку приложения
на устройстве или приёмку Google Play. Итоговый лог — приватный
`.local-backups/recovery-20261016/release-offline.log`.
После проверок выполнен `gradlew --stop`: остановлены два Gradle-daemon.

Исходные 288 файлов сохранены в приватный архив
`.local-backups/recovery-20261016/sources-212546.tar.gz`.
Там же находятся patch рабочего дерева, состояние пакета и системный лог.
Keystore, обе конфигурации подписи и `google-services.json` проверены по SHA-256
на неизменность после обеих сборок; секреты не выводились.
Публикация GitHub/Google Play не выполнялась. Настройки Firebase, Auth и
пользовательские документы Firestore не менялись. Release-пайплайн выполнил
штатную задачу `uploadCrashlyticsMappingFileRelease`; наличие mapping-файла
на сервере отдельно не проверялось.

## Оставшаяся работа

Сначала безопасно восстановить доступ к существующему пакету и проверить текущие
данные AVD. Затем провести native release-приёмку и проверить release SHA/OAuth
в Firebase. Дальнейшие пункты Android: Crashlytics Console, FCM при завершённом
процессе, смена пароля по ссылке, синхронизация двух устройств, камера/GPS на
физическом устройстве. Google Maps ждёт решения о billing; серверные AQI push
не развёрнуты. Остальные продуктовые задачи перечислены в README.
