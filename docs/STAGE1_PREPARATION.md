# Этап 1 — исправления и подготовка Android

Работа и проверки: 15–16 октября 2026 (Asia/Almaty). Облачная настройка не выполняется в этом этапе.

## Что изменено

1. Оба integration-теста запускают актуальный onboarding: «Начать» → выбор → «Продолжить без аккаунта». Сам helper сбрасывает только флаг onboarding и не очищает базу. Для CLI обязательно нужен `--no-uninstall`: иначе runner удаляет пакет при завершении (см. инцидент ниже). Общий helper проверяет оба состояния и сохранение завершения. Smoke-тест прокручивает настройки до темы.
2. Перед первым upload для вошедшего UID выполняется чтение пользователя и избранного с сервера Firestore (`Source.server`). Пока чтение/восстановление не завершено, upload запрещён. Облачные настройки и выбранный город восстанавливаются, избранное объединяется с локальным. Пустой локальный список не является командой удаления. Удаление допускается только после явного снятия отметки пользователем; очередь по UID хранится в SharedPreferences. Версии защищают новую команду удаления от подтверждения предыдущей отправки. Ошибки не стирают очередь, смена аккаунта отменяет устаревшую сессию синхронизации. Повтор — при следующем изменении/обновлении, без бесконечного таймера. Согласование одновременно изменяемых настроек на нескольких устройствах и realtime sync не заявляются. Облачные настройки имеют приоритет при первом восстановлении сессии, локальное разрешение уведомлений не выдаётся автоматически.
3. Актуальность AQI учитывает и `fetchedAt`, и `current.time` модели в UTC. Пределы приложения: получение старше часа, модель старше двух часов или более часа в будущем, либо получение более пяти минут в будущем → нужны обновлённые данные. Новая HTTP-загрузка старого модельного времени не становится свежими данными. Такие отчёты не запускают локальное предупреждение.
4. При неуспешном обновлении сохранённый отчёт содержит исходные timestamps и причину сбоя. UI пишет «Сохранённые данные», сообщает HTTP/JSON/timeout/network-причину; ошибка API не считается доказательством отсутствия интернета. Поле `offline` оставлено для совместимости, его смысл — возврат кеша после сбоя обновления. Production API и модельные значения не заменены fixtures.
5. SQLite keyset pagination для заметок, уведомлений и подробных записей истории: 20 строк + 1 look-ahead, вперёд/назад, loading/error/empty/retry. Сортировка заметок и уведомлений по `(created DESC, id DESC)` защищает от пропуска записей с одинаковым временем. В памяти/виджете текущая страница и история курсоров для возврата. `ListView.builder` строит ограниченную страницу внутри общей прокрутки. Миграция SQLite 2 → 3 добавляет индексы без удаления таблиц. График и календарь используют все доступные точки периода; средние не ограничены страницей. Поиск Open-Meteo оставлен с 15 результатами API: неподдерживаемая серверная пагинация не имитируется.
6. Добавлены проверки доступных экранов на телефоне landscape 740×360 и планшете 800×1280 / 1280×800, light/dark, text scale 1.3, включая прокрутку. Предыдущие 320 px / text scale 1.5 и клавиатура сохранены. Переполнений в этой матрице не обнаружено; утверждённые цвета, фотографии и компоновка не переделывались. Нативная карта без ключа и облачный Account после настоящего входа требуют отдельной приёмки.
7. README и Firebase guide приведены к текущим onboarding, светлому дизайну, кешу, пагинации и безопасному порядку sync. Исторические записи прогресса не являются результатами текущего запуска тестов.
8. Wrapper использует официальный HTTPS Gradle 9.3.1, без `/tmp` в tracked config. На этой машине повторная загрузка была медленной; существующий архив проверен `unzip -tq` и помещён в стандартный HTTPS-кеш Gradle. Сверить SHA-256 с сервером не удалось из-за DNS `downloads.gradle.org`; независимая проверка официальной контрольной суммы не заявляется. Сборка с текущим URL использует стандартный cache. Проверка на совершенно другом компьютере не выполнялась.

## Инцидент с данными AVD

В Flutter 3.47.5 `flutter test` имеет `uninstall=true` по умолчанию (`packages/flutter_tools/lib/src/commands/test.dart`, флаг uninstall; `src/test/integration_test_device.dart`, cleanup). В ранних прогонах был пропущен `--no-uninstall`: cleanup удалил пакет и его локальные данные эмулятора. Затем обычный APK был установлен заново; это не восстановило старую SQLite/фото/настройки. Архив исходников сохранён, но он не является копией app data Android. В доступных локальных копиях старой SQLite не найдено; восстановление старой истории, заметок и фотографий не заявляется. Облачные данные, физическое устройство и исходники не затронуты.

Команды README исправлены. Перед проверкой сохраняющего режима создана текущая копия app data `.local-backups/android-before-preserving-tests.tar` и контрольный приватный файл-маркер. Отдельный прогон обоих тестов с `--no-uninstall` завершён: **2/2 passed**. Контрольный приватный файл-маркер сохранился после обоих тестов и после установки обычного APK через `adb install -r -t`; это отдельно проверено через `run-as ls`. Обычный APK установлен и открыт. Эта проверка подтверждает сохранение текущего состояния, но не восстановление утраченных ранее записей. Никакие модельные точки не генерируются для замены потерянной истории.


Финальная визуальная проверка обычного APK: открыта главная Алматы, выбранный город и светлая тема сохранились после сохраняющего прогона и `adb install -r`. Показан настоящий ответ Open-Meteo: 68 US AQI, время модели 16.10.2026 00:00, получение 00:21 (Asia/Almaty). Снимок сохранён локально: `.local-backups/stage1-checks/android-product.png`. Это новые актуальные данные, а не восстановленная прежняя история.
