# Постоянный application ID: предложение и миграция

25.11.2026. Текущие Android ID `com.example.air_quality_monitor` и iOS Bundle ID `com.example.airQualityMonitor` **не изменялись**.

Предлагаемый постоянный идентификатор для обеих платформ: **`kz.erkezhan.airqualitymonitor`**. Это предложение; уникальность/доступность требуется проверить в Play Console и Apple Developer. После публикации Android package менять для обновлений нельзя.

## План до согласования изменения

1. Сохранить исходники, существующий keystore, JSON/plist и приватную резервную копию данных. Старые Firebase app registrations оставить.
2. Добавить Android и iOS app с согласованным ID **в существующий Firebase-проект**. Сохранить upload key; зарегистрировать его SHA-1/SHA-256 для нового Android app. Получить настоящие google-services.json / GoogleService-Info.plist и OAuth clients/callback schemes именно новых приложений.
3. Проверить Google/Email login, Firestore Rules, FCM и Crashlytics новой регистрации на отдельном стенде. Пользователи и Firestore остаются в прежнем проекте, но сессия нового приложения требует входа.
4. Новый package — отдельное приложение и sandbox: **`install -r` не переносит старую SQLite, фотографии или SharedPreferences между ID**. Облачная синхронизация сейчас переносит настройки/избранное, но не локальные заметки/фото/историю.
5. Перед переходом потребуется реализовать и проверить явный перенос локальных данных (экспорт/импорт с защитой приватных файлов и согласием владельца), либо оставить текущую демонстрационную установку рядом и начать новую установку отдельно. Такой перенос пока не реализован; приложение не обещает автоматический импорт.
6. Только после приёмки выбрать финальный versionCode, проверить новый подписанный AAB и материалы магазина. Старое приложение/данные не удалять.

Без отдельного согласования идентификатор не переключается. Наличие этого плана не является выполненной миграцией.
