# Удаление аккаунта: инструкция разработчику

Рабочие аккаунты не используются для проверки удаления. Локальные тесты применяют mocks, временные каталоги и Firestore Emulator demo-проекта.

1. В приложении пользователь подтверждает удаление и повторно авторизуется. Затем создаётся барьер `accountDeletions/{uid}`: правила отклоняют новые записи профиля, избранного и токенов с других устройств. Ошибка на этом шаге останавливает процесс до удаления данных. Все известные подколлекции `devices`, `favorites`, `notifications`, `alertClaims` удаляются порциями до 200 документов, затем профиль. Auth удаляется последним; Apple grant отзывается перед удалением Auth. Локальное фото профиля удаляется только у этого UID. Общая локальная история/заметки/избранное/настройки сохраняются.
2. При частичном сбое не сообщать успех. Повторная попытка идемпотентна; не снимать барьер и не создавать новый профиль для того же UID. Для ручного обращения сначала подтвердить владение аккаунтом, не запрашивая пароль или 2FA-коды. Удалять только дважды проверенный UID и все его подколлекции; удаление родителя Firestore не является рекурсивным.
3. После подтверждения отсутствия Firebase Auth пользователя и **после `purgeAfter` (не ранее 2 часов)** удалить минимальный технический документ `accountDeletions/{uid}` администратором. Старый ID token живёт до часа; раннее снятие барьера допускает повторную запись. Автоматический TTL/платные задачи не включаются. Без подтверждения завершения Auth документ не удалять: он нужен для безопасного повторения.
4. Сверить отсутствие профиля и четырёх подколлекций серверным чтением. Уведомить заявителя только при завершении. Не включать UID/email/credentials в публичные отчёты. Сторонняя агрегированная диагностика обрабатывается по политике Firebase, не обещать непроверенный purge.

Обновлённые Rules необходимо развернуть до доступности live-удаления. Старые Rules запрещают первый шаг: данные сохраняются, UI сообщает ошибку. Backend scheduler не развёрнут; его исходник учитывает барьер и не восстанавливает удалённые claims после FCM.
