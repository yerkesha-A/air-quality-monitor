# Обработка запроса на удаление: инструкция разработчику

Это процедура для подтверждённого запроса пользователя, а не команда для запуска при тестировании. Подготовка РК2 не удаляет существующие аккаунты или Firestore.

1. Получить запрос на опубликованный контакт и подтвердить владение аккаунтом. Не запрашивать пароль или коды 2FA. Согласовать с заявителем состав данных и сообщить, что локальные данные на других устройствах не стираются удалённо.
2. Найти соответствующий Firebase Auth UID. Проверить его дважды; email других пользователей и ключи доступа не включать в публичные журналы.
3. По подтверждённому запросу удалить документы подколлекций `users/{uid}/favorites` и `users/{uid}/devices`, затем сам документ профиля. Простое удаление родителя Firestore не удаляет подколлекции.
4. Удалить именно соответствующего пользователя Firebase Authentication. Если какой-либо шаг не завершён, не сообщать о полном удалении: закончить обработку и подтвердить результат пользователю.
5. Объяснить заявителю отдельное управление локальными фотографиями/заметками через Android и последствия потери локального кеша. Пароли в Firestore/SQLite приложением не сохраняются.
6. Хранить только минимальные сведения, необходимые для обработки обращения; не обещать автоматическое удаление обезличенной диагностики сторонних SDK, если такая возможность не проверена.

В приложении путь запроса: Профиль → Аккаунт → «Запросить удаление аккаунта» либо «Данные и приватность». Письмо составляется пользователем; приложение ничего не отправляет самостоятельно. Внешняя страница — [ACCOUNT_DELETION.md](../ACCOUNT_DELETION.md), публикуемая вместе с проектом только после разрешения владельца.
